Effect lab — glow techniques

A separate teaching page. The code index stays as it is. These demos run in the phone browser. The host only has to send the file.

A glow is not one tool. It is a blurred copy of a shape, tinted, then painted behind or around the original. CSS, SVG filters, and canvas can all do that. C++, Java, Node, and Drizzle do not draw the glow by themselves.

1. SVG filter glow — the one to learn first

An SVG filter is a little image pipeline. You name the steps. The browser runs them on the shape. This is the technique behind most “delicious” sign-like glows.

<filter id="goldGlow">
  <feGaussianBlur in="SourceAlpha" stdDeviation="6" result="blur"/>
  <feFlood flood-color="#E8C872" flood-opacity="0.85" result="gold"/>
  <feComposite in="gold" in2="blur" operator="in" result="tint"/>
  <feMerge>
    <feMergeNode in="tint"/>
    <feMergeNode in="SourceGraphic"/>
  </feMerge>
</filter>

The letter fill stays solid. The glow is a separate blurred object painted first. That is the “outward halo” you described.

3. CSS glow — what the index is using

CSS text
CSS box
CSS filter
  • text-shadow — halo on glyphs. Cheap. Stays readable if the fill color is solid and the blur is outside.
  • box-shadow — halo on the rectangle, plus inset rings (the green pin and gold hairline).
  • filter: drop-shadow() — follows the real shape, including transparent PNG letters. Heavier than text-shadow.
  • background gradients — the wash behind a title. Not a glow by itself until you blur a copy.
  • mix-blend-mode / background-clip:text — metallic letter fill. Easy to hurt legibility.

5. Language vs effect — do not mix these up

CSS — describes paint: color, shadow, gradient, animation. Works everywhere the file is served.

SVG — drawing plus a filter graph. Best when the glow must follow letters or a logo path.

JavaScript — turns effects on, reads a field, swaps a class. Canvas and WebGL live here.

PHP — builds the page on Hostinger before it is sent. It does not animate. The browser does.

Node — JavaScript on a server. APIs, sockets, file watchers. Not a glow.

Drizzle — a Node/TypeScript library that writes SQL. Zero pixels.

Java — server or Android apps. Not available as the page renderer on this Hostinger site.

C++ — native apps, game engines, sign-controller firmware. A web page cannot compile C++ on Hostinger. A prebuilt WebAssembly file can run in the browser, which is the wrong tool for a title glow.

SDK — a kit from a vendor (maps, LED players, payments). You call it. You do not “write an SDK glow.”

6. How to ask for the next look

  • “SVG gold glow under the city name, letters stay #071614, blur 6, opacity .4.”
  • “CSS only: inset 1px green, 1px gold, 6px dark outer, no SVG.”
  • “Pulse the gold halo 2.5s, ease-in-out, do not move the card.”
  • “Do not use canvas. Must work as one HTML file on Hostinger and on the phone.”

For the Alpha CRM pages, stay on CSS and inline SVG. Upload the HTML/CSS into public_html. Do not add Node, Drizzle, Java, or C++ to get a prettier card.
